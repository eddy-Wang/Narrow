# 在线意图链路隔离检查（2026-08-30）

## 原因

原实现虽然开启 LLM，但 understand_user 每轮先运行 rule_state_patch；
resolve_semantic_patch 又在 LLM 成功后合并 semantic_fallback_patch 的约束、
删除字段、无偏好字段、类别和 retire_soft，并把混合结果标记为 deepseek。
因此 parser=deepseek 不能证明历史约束完全来自模型。

public_0024 第三轮的 `without sacrificing.` 可以触发本地否定解析，产生
`feature not_contains sacrificing`。旧 trace 没有单独保存模型输出，不能据此
断定模型是否也返回过该约束。检索意图另有启发式推断；语义和对话调用失败
都曾静默降级离线策略。这些入口已隔离。

## 当前边界

| 环节 | 在线行为 |
| --- | --- |
| 用户理解 | 不调用本地解析，不向模型传 rule_patch；约束、强弱、删除、替换、无偏好、类别、查询和 retrieval_intent 来自模型 |
| 校验 | 校验字段类型、规范化空白、去重；同属性同值的正反冲突报错，不自动选择负约束 |
| 状态更新 | 执行模型 patch 并继承未修改的历史状态，不用规则补充本轮语义 |
| 查询构建 | 将模型约束和查询序列化给检索器；明确 unknown 不再被启发式改写 |
| 召回、粗排、过滤、精排 | 保留索引、数值特征、训练权重和约束执行器；不从用户文本额外生成结构化约束 |
| 候选统计 | 属性分布和信息增益是提供给模型的证据，不是在线追问决策 |
| 对话决策 | 追问/推荐/确认/结束、追问属性及文案由模型返回，不调用离线 choose_question，不传 fallback_suggestion |
| 回复校验 | 限制真实商品 ID、去重、Top K 和合法属性，不让模型创造商品 |
| 失败 | 开启 LLM 但缺密钥、调用失败或响应非法时明确报错；不自动运行离线策略。原有短暂故障重试保留 |
| Trace | semantic_patch.model_output 保存解析后的模型意图（不是原始响应文本）；dialogue_parser / dialogue_model_output 保存对话来源和输出；候选仍默认全量保存 |

SHOPPING_AGENT_ENABLE_LLM=false 时离线解析与追问策略仍可用于独立基线测试。
整个检索图仍是固定执行图，不是任意工具调用 agent：模型决定结构化输入与
对话动作，代码执行检索排序。本次不改变已训练的排序特征和权重。

## 验证及历史结果

73 项测试通过。新增三轮完整图测试，把本地解析器和离线追问策略替换为一旦
调用就失败的哨兵，验证含 `without sacrificing.` 的输入不会被规则注入负约束，
目标仍在结果中，模型 unknown 意图被保留，trace 可追溯模型输出。
另外验证缺密钥、语义调用失败、非法响应、对话超时和正反约束冲突不会隐式降级。
这些是受控模型输出的回归测试，并不证明真实 LLM 永远不会误解用户。
