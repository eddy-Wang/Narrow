主要的优化方向。

## 最重要的行为发现

澄清策略在 200 个会话的首轮中，有 199 次询问了 `brand`。从数学角度看，
品牌具有较高熵，因此这种选择可以理解；但它会产生涉及生僻电商品牌、对真实
用户不友好的问题。仅凭候选集熵不足以衡量一个问题的实际价值。

所有轮次中的问题统计：

| 属性 | 次数 |
|---|---:|
| brand | 200 |
| style | 89 |
| material | 70 |
| use_case | 64 |
| color | 62 |
| budget | 43 |
| 未提问 | 113 |

下一版策略应将预期候选缩减量、用户可回答性和业务相关性结合起来。一个实用的
默认优先级是：使用场景、类别/形态、材质、功能特征、尺码、风格、预算、颜色，
最后才是品牌；除非用户已经主动提到了品牌。

## 分场景观察

- Buying 场景的命中速度最好（`MTTC=2.4375`）。
- Intent Override 场景的排序质量最好（`MRR=0.489854`），但由于模拟器会在
  会话中途改变意图，它自然需要更长时间（`MTTC=5.0`）。
- Boundary 场景的命中率较高（`0.9`），但 MRR 最低（`0.250397`）。这说明
  用户回答“无偏好”之后，当前重排序器仍不能有效聚焦结果。
- Browsing 是规模最大的场景，并且有 9 个未命中案例，因此下一次定性错误分析
  应以该场景为重点。

## 建议开展的下一批实验

1. 用问题效用分数替代原始熵：惩罚生僻品牌和高基数品牌，奖励用户容易回答的属性。
2. 在关键词、语义、属性、融合、过滤和重排序阶段跟踪目标商品是否出现及其排名，
   从而区分召回失败和排序失败。
3. 用计划中的 Embedding/向量数据库实现替换哈希语义兜底，并比较各召回通道的召回率。
4. 尝试学习式重排序器或 LLM 重排序器；当前命中率与 MRR 之间的差距说明候选排序
   是主要瓶颈。
