# LambdaMART Training and Feature Contract

[Chinese](lambdamart_training.zh-CN.md) · [Current MRR objective](mrr_training.md) · [Selected-bundle comparison](mrr_loss_search_20260901.md)

This document records the base LambdaMART experiment, data separation, runtime
features, and reproducibility checks shared by the current ranking bundles.
The active bundle was selected later through the bounded MRR-loss comparison
linked above; its exact hashes are in the
[bundle README](../models/lambdamart_synthetic_2000/README.md).

LambdaMART replaces only the final reranker. Coarse retrieval, RRF fusion, hard
constraint filtering, dialogue state, and the Precise baseline remain separate.
Its input is the candidate set and known intent for a turn, and its output only
reorders those candidates. It cannot read the hidden target, intent card, or
simulator answers. `parent_asin` is used only to derive the previous-recommendation
`novelty_penalty`; it is not a learnable product-ID feature.

## Learning task

The task is listwise learning to rank, not independent binary classification.
One conversation turn and its candidate list form a query group. The learner
tries to place the designated product near the front of that group.

Labels come from the local evaluator: the candidate matching
`ground_truth.parent_asin` receives 1 and all other candidates receive 0. This
is weak supervision for retrieving a designated product. A zero label does not
mean that an item is irrelevant to every real shopper, so model scores are not
purchase probabilities or general relevance judgments.

Training avoids manufactured positives:

- Only candidates produced by actual retrieval, fusion, and filtering are saved;
  a missing target is never inserted.
- A group is trainable only when it contains the target and at least two
  candidates; all-negative groups contain no ranking pair and are dropped.
- `intent_override` contributes training groups only after the intent changes.
- Each valid group receives weight `1 / valid groups in the session`, preventing
  longer conversations from dominating the fit.

## Data separation and split

The experiment uses `data/synthetic_scenarios_2000.jsonl` (2,000 synthetic
scenarios covering 571 target products) and the fixed 200-scenario
`data/public_set.jsonl`. Retrieval always uses the complete 50,000-product
catalog. Separation removes supervised scenarios; it does not remove public
target products from the catalog.

All 418 synthetic scenarios whose target also appears in the public set are
removed first. The remaining scenarios are split by **target product**, not by
row, so scenarios for one product cannot cross training and validation. The
seed is `20260830` and the validation share is 20%.

| Split | Scenarios | Distinct targets | Purpose |
|---|---:|---:|---|
| Training | 1,291 | 368 | Fit the tree model and same-data linear control |
| Validation | 291 | 92 | Early stopping and training-only model choice |
| Public development | 200 | 200 | End-to-end development comparison; never used for gradients |

The original candidate trajectories were generated by complete offline
conversations driven by `PreciseReranker`, then recorded for training. The new
tree and same-data linear models are separated from public targets, but the old
Precise weights had previously seen the full synthetic set. The separation
claim therefore applies to these new supervised fits, not retroactively to
every component in the end-to-end system.

The base collection produced 3,587 training groups and 1,749,029 candidate
rows, with targets present in 2,650 groups. Validation produced 781 groups and
385,343 rows, with targets present in 576 groups.

## Runtime features

Schema version 1 fixes the following order. Loading fails when names or order
do not match. Every feature is derived from the current candidate, query,
category and constraints, user profile, or recommendation history.

| Feature | Meaning |
|---|---|
| `exact_matches` | Number of explicitly satisfied constraints, including a satisfied budget |
| `partial_matches` | Term coverage for constraints that do not match exactly |
| `category_match` | Whether the normalized category phrase appears in product text |
| `term_coverage` | IDF-weighted query-term coverage in product text |
| `lexical_signal` | `1 / lexical_rank` |
| `rrf_raw` | Upstream reciprocal-rank-fusion score |
| `dense_raw` | Raw dense-retrieval score |
| `attribute_raw` | Raw attribute-index score |
| `profile_match` | IDF-weighted coverage of user preference tags |
| `quality` | Smoothed rating with prior 4.0, weight 20, divided by 5 |
| `contradictions` | Count of conflicts between explicit product attributes and soft constraints |
| `budget_penalty` | Normalized penalty above or below the requested budget |
| `novelty_penalty` | 1 when the product was recommended earlier in the session |

`term_coverage` and `profile_match` use a catalog-wide IDF table frozen as
`idf.json`, not statistics recomputed on each candidate batch. Product text
combines title, categories, features, details, and store. Raw retrieval scores
are not normalized per batch, so a product's feature values do not drift merely
because the surrounding candidate set changes.

## Base learner and controls

The base experiment used LightGBM 4.7.0 `LGBMRanker`, a `lambdarank` objective,
and `ndcg` validation metric:

```text
objective=lambdarank          metric=ndcg
n_estimators=300              learning_rate=0.05
num_leaves=15                 max_depth=5
min_child_samples=40          reg_lambda=5.0
lambdarank_truncation_level=13
random_state=20260830         deterministic=true
force_col_wise=true           n_jobs=4
```

Early stopping on synthetic-validation `NDCG@10` with patience 30 selected
`best_iteration = 167`. The public 200 did not choose features, hyperparameters,
or tree count in this base experiment. Save/load verification compares the
fresh booster with `LambdaMARTReranker` predictions on the first 500 validation
rows at tolerance `1e-12`.

A `LogisticRegression(C=100, class_weight=balanced, max_iter=3000)` control is
fit with the same rows, labels, features, and session weights. It separates the
effect of tree capacity from the training-data change and is not the runtime
ranker. The later MRR rounds retain the same 13-feature runtime schema and are
documented in [mrr_training.md](mrr_training.md).

## Frozen bundle and validation

The committed `models/lambdamart_synthetic_2000/` directory is self-contained:

| File | Purpose |
|---|---|
| `model.txt` | LightGBM tree ensemble used by the runtime |
| `idf.json` | Catalog-wide IDF values frozen with training |
| `metadata.json` | Feature schema, parameters, data summary, hashes, and split policy |
| `same_data_linear_weights.json` | Audit control; not used by the primary runtime |

Runtime loading rejects incompatible schema versions, feature order, IDF, or
prediction shape. Scores are relative ranking margins, not probabilities. Ties
are resolved by the smaller lexical rank.

For historical context, the base end-to-end offline simulation on the public
200 produced the following results. These are development measurements, not an
unseen leaderboard estimate, and they are not the final Flash selection:

| Reranker | Hit@10 | MRR | MTTC | Technical score | Median rerank latency |
|---|---:|---:|---:|---:|---:|
| Original Precise | 87.5% | 0.4119 | 3.695 | 0.7072 | 16.45 ms |
| Same-data linear | 91.0% | 0.4388 | 3.430 | 0.7381 | 16.40 ms |
| Base LambdaMART | 92.0% | 0.4781 | 2.875 | 0.7659 | 18.13 ms |

In a frozen-candidate comparison, average per-session turn Hit@10 / RR /
NDCG@10 was `0.7347 / 0.4227 / 0.4911` for LambdaMART versus
`0.6011 / 0.3091 / 0.3674` for Precise. The paired bootstrap difference in
complete-session technical score versus the same-data linear control was
`0.02789`, with a 95% interval of `[0.00559, 0.05173]`. This estimate applies
only to the local evaluation.

## Reproduce the base experiment

Training does not call an LLM, disables remote tracing, and forces local dense
retrieval. Supply the ignored `data/catalog.jsonl` and the synthetic file whose
SHA-256 is `5948baae33053d13a0506c9a895d0857cdd5b26fbe247bd18437ece21769f7af`.
From the repository root:

```powershell
.\run_local_python.ps1 scripts/experiment_lambdamart.py `
  --synthetic data/synthetic_scenarios_2000.jsonl `
  --output evaluation_runs/lambdamart_synthetic_2000_reproduced
```

Use a new output directory; the script refuses to overwrite an existing run.
After training, inspect the catalog, public-data, feature-source, and script
hashes in `model/metadata.json`. Different data or dependency versions are not
guaranteed to reproduce identical `model.txt` bytes.

## Runtime boundary

Online evaluation loads the frozen bundle while the LLM handles only intent
understanding and dialogue decisions. Select it explicitly with
`--ltr-ranker lambdamart --ltr-model-dir models/lambdamart_synthetic_2000`.
The ranker cannot repair upstream recall misses, missing discriminating
information, or a target absent from its candidate set; its responsibility is
to order candidates that reach the reranking stage.
